## 背景与根因

真机报错（原样）：
`附着常驻浏览器失败（port=59968）：BrowserType.connect_over_cdp: Protocol error (Browser.setDownloadBehavior): Browser context management is not supported.`

链路：venv 重建后 playwright 升到 1.63.0，但旧 venv 起的无头守护还活着（活了一天多），
session.json 验活只探 pid + HTTP 端口（`daemon_info`），CDP 协议层不兼容要到
`connect_over_cdp` 握手才炸；炸了之后原代码直接向上抛，要人手动 `pageplay shutdown`
再重试。

## 改动（只动 session.py + tests/test_daemon.py，无 git 操作）

### pageplay/session.py（484 → 500 行，压线 ≤500）

1. **connect 动作收敛为可注入小函数**（session.py:140 `connect_cdp(url)`）：
   `_driver().chromium.connect_over_cdp(url)` 唯一入口，测试 monkeypatch 点；
   `_connect`（session.py:145）改调它并保留人话包装（含 shutdown 兜底提示）。
2. **ensure_browser 附着失败自愈**（session.py:178-197）：附着分支套 try/except，
   任何异常 → `log.warning("附着失败…自动重启守护…")`（:191）→ `shutdown_browser()`
   （复用现有 SIGTERM 流程，杀旧守护清 session.json）→ 走既有起守护路径重试；
   重试成功 `log.info("守护已自动重启")`（:194）；重试失败向上抛（connect 路径经
   `_connect` 保留 "可执行 pageplay shutdown 后重试"）。**不递归、恰好重试一次**
   （自愈直接调 `_launch_daemon`，不再进附着分支）。连接拒绝语义不变：端口没服务
   在 `daemon_info` 验活阶段判死走起守护路径（现状保留）；验活后连接中断/协议不
   兼容走自愈——并入、不重复。
3. **起守护路径抽成 `_launch_daemon(headless)`**（session.py:200）：首次起守护与
   自愈重启共用同一条路径（unlink → executable 检查 → Popen 脱离父进程 → 轮询
   30s → connect → 写 session.json），行为与原内联代码逐行一致。
4. **session.json 增记 `pw` 驱动版本**（session.py:81 `_write_session`，统一写
   入口）：`importlib.metadata.version("playwright")`，成功附着后重写一次
   （session.py:195，port/pid 不变、pw 刷新）、起守护成功后写入（session.py:237）。
   仅作诊断信息，不做主动重启（避免误杀可用会话）。daemon_info 只读
   port/pid/headless，旧文件无 pw 字段照常解析（向后兼容）。

行数达标说明：新增约 34 行、预算 500，除收紧自身新增 docstring 外，对相邻三个
守护帮手（`_driver`/`daemon_info`/`ensure_headful_browser`）docstring 做了等
信息压缩（合并换行，内容不丢）以及附着日志并 1 行，最终恰好 500 行。
