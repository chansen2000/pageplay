## 测试（6 条，全部真 chromium）

- happy path：goto/click/table/click/download 五步全 ok；happy-3.csv
  /json 两列三行内容逐项断言；report.csv 字节体一致；完事页已收。
- 显式 stem：产物名 `<stem>-<no>` 优先于 flow 名。
- 登录反弹协作成功：/private 反弹 → 协作种 cookie → 重试通过 → 后续
  table 步继续；协作调用计数 ≤ 2。
- 登录反弹协作失败（False）：ok=False + failed_step=1 + 人话 detail
  （"登录态失效…未通过"）；照 cli_pick 语义等待未通过不再重试。
- 中途步选择器超时（SELECTOR_TIMEOUT_MS patch 成 400ms）：该步 fail
  "第 2 步卡住：页面结构可能变了"，results 长度 2（后续步未执行），
  产物目录根本没建（无落盘动作的强证明）。
- 真风控：中性主机页面含"滑块" → RiskTriggered 向上抛，页已收。

## 关键决策

1. **自持 `_goto_with_login_recovery` 而非 import cli_pick**：T11d
   会从 cli 侧调 runner，runner 反向 import CLI 层顶层会成环；任务书
   明示允许等价实现。语义与 cli_pick 逐条对齐（消息文案、重试上限、
   Guard 命中在登录页的分流）。
2. **测试文件完全自持**（T11b 对 conftest 有并行独占追加权）：假站、
   守护夹具、"人过"替身全部内联本文件，零 conftest 依赖。
