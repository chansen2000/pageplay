## local 引擎实现链路（vision.py）

```
screenshot_table(page, engine="local")
  → screenshot_local(page)        # png 字节 → tempfile(.png)，用完即删（finally）
  → extract_local(png_path)
      ① _extract_bordered_table   # img2table+tesseract(chi_sim+eng) 有边框表格
      ② ①无数据行 → _ocr_text_blocks + _cluster_text_blocks
                                  # rapidocr 全文块 → x 空隙分栏 + 栏内 y 聚类
  → 两级都空 → []
```

## 实测钉死的关键事实（非推断，全有实验依据）

1. **img2table 2.0.0 边框表的 df 首行就是表头行**（4x4 实测）→ 选"首行作列名"
   而非合成"列N"，用户拿到真列名（订单号/价格…）；df 只有表头一行 → 落到第二级。
2. **img2table 2.0.0 的 `df` 是属性不是方法**（`t.df()` 报 'DataFrame' object is not
   callable）→ `callable()` 双兼容旧版。
3. **tesseract 中文插词间空格**：实测输出 "订单 号"/"已 发 货"/"机 械 键盘"，连列名都带
   空格 → 加 `_squeeze_cjk_spaces`：只去两侧都是汉字的空格（CJK-CJK），英文/数字间距
   保留（"商品A"/"iPhone 15" 不动）。这是 OCR 后处理通行做法，不是内容改写。
4. **分栏/聚类参数实测有效**：800px 图、8% 阈值=64px，两栏中心距 373px 干净切开；
   栏内行距 42px 远大于 8px 聚类容差。
5. **OCR 瑕疵容忍**：tesseract 对个别单元格会缺字（实测"无线鼠标"一格读空）→ 测试
   断言只锚稳定事实（订单号数字、价格、文本集合），不锚易抖动单元格。

## 边界

- local 引擎第①级只认有边框表格（img2table 缺省 borderless_tables=False），
  无边框走第②级聚类——两级口径在 docstring 写明。
- 临时 png 在 screenshot_table local 路用完即删；screenshot_local 单独用时调用方自删。
- engine 非法值：vision.screenshot_table 抛 ValueError（校验点唯一），CLI 无 choices
  约束（代码库无先例），由 main 统一映射"执行失败：未知的视觉引擎…"退出 1。
