# T20b：消灭"抓表 0 行"误报（sheng 两次真机 0 行的根修）

日期：2026-09-25 ｜ 基线：git fe02d2e (v0.8.1) ｜ 状态：✅ 完成（全量 398 passed ×2）

## 根因（主 agent 真机取证）

1. 框选层 hover 语义优先 `SEM = "table,ul,ol,[role=grid]"` 含 ul/ol：锁中语义列表容器后走
   extract_table，而列表容器没有 tr → 永远 0 行
2. 红框对所有锁中目标视觉相同：点击前无从分辨卡片组（字段勾选）与普通容器（两按钮/空列勾选）
3. 提取 0 行仍报 "✓ 已生成：抓表 0 行"、退出码 0——失败被当成功

## 改动

| 文件 | 改什么 |
|------|--------|
| `pageplay/_overlay_js.py` (317 行) | ① SEM 收窄为 `"table,[role=grid]"`，ul/ol 卡片组由 cardGroup 认领走字段勾选；② 红框挂类型标签 `#__pageplay_boxlabel`（跟随 box 左上角、锁定后保留）：卡片组 → "卡片列表：N 条记录"、table/[role=grid] → "表格：N 行"、其他 → "元素（无表格结构，仅可下载）"；③ renderColumnBar 无列 → 确认置灰 + 红字"该目标读不到列（无表格行），按 Esc 换目标"；renderActionPanel 无 tr → 不渲染"抓取此表"，只留下载 + 灰字"该元素无表格结构，不可抓表" |
| `pageplay/actions.py` (216 行) | extract_table 防呆：`columns=[]` → ValueError"至少勾选一列"；提取结果无数据行/无列名 → ValueError（`ZERO_ROWS_PREFIX = "提取到 0 行"` 开头的人话，指引"看到「识别到 N 条记录」的面板再确认"）。异常从 _execute_and_record 的通用失败路径出 → ✗ + fail 账，pick/record/grab/run 四条路全部不再有 0 行假成功 |
| `pageplay/cli_pick.py` (499 行) | `_execute_recipe` 按 list_mode 分派 extract_cards/extract_table（卡片确认当场出真数据，对齐 runner）；`_execute_and_record` 返回 `(产物, 失败原因)` 并透传 list_mode/fields；`confirm_and_execute` recipe 存 list_mode/fields（卡片 recipe 可重放）、返回失败原因；pick 会话出现 0 行 → 退出码 1（会话不中断继续下一条）；record 收获步透传 step 的 list_mode/fields |
| `pageplay/cli_grab.py` (100 行) | `_handler` 解构新返回值 + 透传 list_mode/fields；0 行 → picked ok=False → 退出码 1（原有机制自然生效） |

## 行为变化（有意为之）

- 0 行提取在所有路径 = ✗ 失败 + fail 落账：pick 会话退出码 1、grab 退出码 1、run/flow 该步失败
- pick/record/grab 确认卡片组（"识别到 N 条记录"面板）当场真抓卡片（此前走 extract_table 必 0 行）
- pick 退出码只对 0 行失败置 1；其他单条失败（如下载超时）维持既有会话退出码 0（test_pick_repeat_two_confirms 契约未动）
