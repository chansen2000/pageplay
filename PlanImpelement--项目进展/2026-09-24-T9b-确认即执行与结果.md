### 2. pageplay/cli_pick.py（新建，242 行：pick/run/results 处理函数自 cli.py 拆出）

- 拆分约束：test_cli.py 的替身是 `monkeypatch.setattr(cli, "SiteSession", Stub)`，
  故本模块顶层只 `from . import cli as _cli` 绑定模块对象，SiteSession 等
  共享底层一律 `_cli.属性` 调用期取用（monkeypatch 才生效）；cli.py 在
  `_build_parser` 内延迟 import 本模块，顶层互不 import，任何导入顺序不循环。
- `confirm_and_execute(page, site, site_dir, name, result)`：单条确认闭环
  （T9a 的 repeat 下一棒直接复用本函数）——存 recipe → 当场执行 →
  ✓（产物绝对路径+大小）/ ✗（人话原因）→ 无论成败 record_run 落账。
  全函数不向上抛：单条失败记 fail 账，pick 会话继续。
- `_execute_recipe(page, recipe, out_dir)`：单次执行共用体（table 抽表落盘 /
  download 下载），pick 即时执行与 run 重放同用，返回 (行数, 产物路径)。
- `_cmd_pick`：on_confirm 钩子从"回显选择器"升级为 confirm_and_execute；
  recipe 在钩子内保存（原来在 run_pick 返回后保存）；封面图与 run 指引不变。
- `_cmd_run`：执行完打 `✓ 已生成：抓表 N 行 → 绝对路径（大小）` /
  `✓ 已生成 绝对路径（大小）`；失败打 ✗ 人话（含"点击后没有触发文件下载——
  选的可能不是下载类元素"、"页面结构可能变了，请重新 pick <站点>"），
  结果无论成败落账。RiskTriggered 不接——照旧穿透 main 映射退出码 2。
- `_cmd_results`：`pageplay results [recipe名] [--limit N]`，只读视图永远 0；
  每行 时间/recipe/动作/✓✗/产物路径（成功）或失败原因（失败）。
- `_runs_path()`：PAGEPLAY_HOME 下 runs.jsonl（与 sites 根同级，默认
  ~/.pageplay/runs.jsonl）。

## 本任务钉掉的两个坑（后续接线注意）

1. monkeypatch 生效路径：test_cli.py 的 SiteSession 替身打在 pageplay.cli
   命名空间上——cli_pick 处理函数必须 `_cli.SiteSession` 调用期取属性，
   `from .cli import SiteSession` 拷贝引用会让替身失效。
2. pick 即时执行产物目录 = run 默认目录（~/Downloads/pageplay/<recipe名>/），
   测试里必须 monkeypatch HOME，否则写进真实下载目录。
