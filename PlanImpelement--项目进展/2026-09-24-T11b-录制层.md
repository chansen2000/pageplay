## 为什么 / 实现链路

契约（T11b 任务书 + 设计文档 §12）逐字落地，复用 picker 不改 picker.py：

1. **recorder_js()**（recorder.py:124，JS 体 :40）：IIFE 幂等单实例（首行
   自清旧监听，同 picker 模式）。document 级 click capture + passive 只记
   不拦：target 链 hint（与 selector_from_chain 同规则）+ 最近 a[href] 的
   href + location.href，经 `window.__pageplay_step` 即时回传（导航杀 JS
   不能攒）；keydown "p"（activeElement 非 INPUT/TEXTAREA）置
   `window.__pageplay_picking = true`（挂 window：python 收尾要清、测试
   要观测）并发 `{kind:"pick"}`。新文档由 add_init_script 自动布防，
   picking 复位为浏览态。
2. **merge_click_step()**（recorder.py:129）：纯函数，click payload →
   `{"no","kind":"click","url","selector","note"}` 追加返回新列表；
   note 记 href，final_url ≠ 点击时 URL 时改记落点。
3. **record_session()**（recorder.py:247）：expose_function 绑定 +
   _ACTIVE 路由（仿 picker._ensure_bindings 的 already-复用）→
   add_init_script + 当前文档补 evaluate（T8 经验）→ FIFO 队列排空 +
   event 等待主循环。click → merge → on_step → 3s 窗口补落点（URL 比较，
   :222 `_await_landing`）；pick → picker.run_pick 单条模式（:196
   `_enter_pick`），收获步 `{no,kind=action,url,selector,columns,note}`
   追加并调 on_harvest(step)。退出语义：关窗/空闲 600s/Ctrl-C，
   ≥1 步返回全部、0 步 PickCancelled（:183 `_finish`）；Esc 只取消框选
   回浏览，不结束会话。

## 关键修复点 / 踩坑

- **picker overlay init 脚本污染**：run_pick 内部 add_init_script(overlay_js)
  会让此后每个新文档自动布防 overlay，首页首击被截获锁定，破坏"自然浏览"。
  解法：首个框选结束后注册清场 init（:113 `_DISARM_PICKER_INIT`），
  新文档加载完立即拆 picker 布防。e2e 用 sessionStorage 见证回访 /start
  覆层不在场。
- **Chrome 对 goto 页面忽略脚本关窗**（实测 Chrome for Testing 153：
  window.close / 先跳 about:blank / window.open('_self') 三种写法全部
  无效，is_closed 恒 False；set_content/about:blank 形态有效）。
  处置：关窗退出路径用 set_content 页面专测（同 test_picker_repeat 手法，
  走同一条 Page closed → _finish 代码路径）；需真导航的 e2e/Esc 用例改用
  空闲超时退出（同为契约退出路径"≥1 步返回全部"），页面存活反而便于
  直接断言 sessionStorage 见证。
