## 改了什么

### 1. 两个纯函数（pageplay/gui.py，模块级，挨着 next_record_name）

- `latest_csv_output(runs_path)`（gui.py:127）：从 runs.jsonl **末尾向前**找第一条能解析的记录；坏行（JSON 损坏/非对象）跳过继续向前；该记录 `status=ok` 且 `outputs` 里有 `.csv`（取最后一个）→ 返回路径，否则 None。只认最后一条有效记录，不回看更旧收获；文件不存在/空文件 → None。
- `load_csv_for_preview(path, max_rows=500)`（gui.py:159）：`pandas.read_csv(dtype=str, keep_default_na=False, encoding="utf-8-sig", nrows=max_rows)` → `(表头, 行)` 全文本。不存在/空文件/解析失败 → ValueError（人话）。**截断探测约定**：调用方传 `max_rows+1`，多返回一行即证明被截断——GUI 用此法打"仅显示前 N 行"标记，不猜不误报。
- `_runs_jsonl_path()`（gui.py:121）：账本路径，与 cli_pick 同款（PAGEPLAY_HOME 覆盖，默认 ~/.pageplay/runs.jsonl）；GUI 只读不写。

### 2. GUI 接线（App）

- `_on_done` 正常结束分支（gui.py:348）调 `_maybe_preview()`（gui.py:425）：查账本 → 有 csv → `max_rows+1` 读数据 → 截断标记 → 记日志 `已弹出数据预览：<名>（N 行[，仅显示前 500 行]）` → `_open_preview()`（gui.py:447）。预览是锦上添花：任何 ValueError 只记一行日志，不弄崩控制台。
- `_open_preview()`：Toplevel 标题"数据预览：<文件名>"；ttk.Treeview（columns=表头，show="headings"，横竖滚动条各一，只读）；底部 Label"已保存：<绝对路径>（<大小>）"（`from .actions import file_size_str`，gui.py:35；guard 纯标准库无重依赖代价）。多次收获多个窗，互不替换。
- `PREVIEW_ROWS = 500` 类常量（gui.py:200）；pandas 延迟导入（gui.py:180，预览用到才加载，GUI 启动不背其开销）。

## 关键修复点（冒烟抓到的 bug）

首版 `_open_preview` 建了表格和表头但**忘了插入数据行**——真 Tk 冒烟（临时脚本，未入库）显示日志记"1 行"而 `get_children()` 为 0，当场补 `tree.insert("", "end", values=row)`。另实证：Treeview 显示层持有原始文本（`tree.set()` 回读 `'001'`），`item()["values"]` 读回 int 是探针路径的整型亲和假象，非显示 bug。

## 实测证据（pandas 3.0.6）

- `dtype=str, keep_default_na=False` 全列 str："001" 不变形、空单元格是 ""、短行缺格自动补空串；
- `utf-8-sig` 兼容 save_table 带 BOM 产物（列名干净，BOM 不漏进首列）；
- 空文件抛 EmptyDataError（ValueError 子类），转人话。
