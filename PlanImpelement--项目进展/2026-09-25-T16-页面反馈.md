# T16：页面视觉反馈 + 操作步骤引导（2026-09-25）

## 改了什么

sheng GUI 验收反馈「盲操作」：用户不知道系统在听、在录、框选落在哪个标签页。
本次三路落地（步骤卡 / 页面反馈 / 注入位置明示），CLI 是唯一真相源，GUI 日志窗
经 stdout 自动透传，gui.py / session.py / picker.py 本体零改动。

### A. 启动步骤卡（cli_pick.py / cli_grab.py，直接 print）

- record 启动：4 步编号卡（正常浏览 / P 键或「框选」按钮 / 数据当场落地 /
  关标签页或「取消」结束起名）。
- pick / grab 启动：3 步框选卡（移到目标 → 单击锁定 → 勾列/勾字段确认落地）。
- run 启动（整链与单条 recipe 两路径都打、各一次）：3 步执行卡（逐步执行 /
  被弹登录页去窗口过验证 / 产物路径最后列出）。`_cmd_run` 双查顺序微调为
  「先双查再打印再派发」，行为语义不变。

### B. 录制中页面反馈（recorder.py 内嵌 _RECORDER_JS 增强）

- REC 角标：右上角「● 录制中 [框选]」，半透明、容器 pointer-events:none、
  仅按钮可点；按钮点击 = 等价按 P（同 enterPick 入口，send {kind:"pick"}）。
- hover 轻高亮：1px 虚线 outline（不改布局），mouseover 换目标即清旧、
  mouseout 移除；INPUT/TEXTAREA/角标/弹条/picker 覆层豁免；框选子模式期间
  不生效（overlay 自有红框，避免打架），还原行内原值。
- P 键弹条：顶部居中「框选模式：红框罩住目标后单击锁定（Esc 返回浏览）」，
  进子模式即时出现，持续到锁定/取消（python 清 picking 标记后由 500ms 心跳
  切回，角标同步恢复）。
- cleanup（__pageplay_rec_cleanup）：拆 4 个监听 + 心跳 + 还原高亮 + 移除
  角标/弹条，随会话结束一并收掉；全部 append+移除，不改业务 DOM。
- 点击照常放行原则不变：角标 UI 点击不记为步骤（onClick 新增角标豁免）。

### C. 框选注入位置明示

- grab：原「将从此页取数据」行按任务书措辞升级为
  「框选已激活在标签页：<title>（<url 前 60 字>）」（同一用途不重复打两行，
  tests/test_grab.py 两处断言同步更新）。
- pick：goto 后新增同款行；title 取不到回落「（无标题）」。

## 为什么改 / 根因

不是代码 bug，是「系统状态对人不可见」的产品缺口：录制/框选是否布防、快捷键
是什么、落在哪个标签页，全靠猜。解法按信息出现的时机分三层——命令启动时
（步骤卡）、页面里常驻（角标+hover）、进框选时（弹条）+ 注入时刻（标签页明示）。
